# RE-001 v0.6.2 — Functional Depth & Evidence Integrity

**Status:** Proposed implementation plan, awaiting approval.
**Prerequisite:** v0.6.1 design review and UO-001 locked outcome.
**Objective:** One credible end-to-end engineering investigation, not a new product architecture.

## Target operator journey

1. Open a known regression (e.g. synthetic SD-081) from the case explorer.
2. Inspect the baseline decision path and candidate path; clearly mark whether each is a projection or an evaluated execution.
3. Select a routing node or edge and inspect the applicable rule, runtime-observed classification, selected route, attempt, outcome, cost and evidence IDs.
4. Edit an ordered bounded routing rule; preview affected case counts and graph branches from runtime-available inputs.
5. Run matched baseline/candidate evaluation on the versioned 100-case synthetic cohort; persist exact policy revision, cohort hash and evaluator version.
6. Filter regressions and select one; reveal the first actual differing decision, not a hardcoded assertion.
7. Revise to a bounded route; rerun and compare quality, policy violations, latency and cost per verified outcome.
8. If gates pass, review and activate exactly that frozen revision in the local simulation; run separate post-activation verification; restore S0 and preserve history.

## Implementation slices (ordered; stop at gates)

### F1 — Typed evidence foundation
- Define Case, ObservedClassification, PolicyRevision, Rule, Decision, Attempt, EvaluationOutcome, CostLineItem, Cohort and EvaluationRun.
- Link records by stable IDs; retain evidence origin (synthetic simulated, fixture replay, observed live only when truly available).
- Runtime-observed classification MUST be separate from reference/ground-truth category; the policy engine cannot read ground truth.
- Each case's baseline and candidate decision chain must be reconstructible.
- Cost line items and escalation-labor estimates separately labeled; all aggregates reconciled from underlying records.
- Deliver unit tests for classification leakage, referential integrity, determinism, cost reconciliation.

### F2 — General bounded routing policy
- Ordered rules for economy vs premium, safe default and explicit fallback; deterministic evaluator over observed fields.
- Revision hash changes with every edit. Edits invalidate prior evaluation eligibility.
- Preview routing derived from same policy evaluator as simulation; never a parallel hand-authored counter.
- Unsupported conditions fail closed as inconclusive; no candidate-name allowlists.
- Test first-match priority, fallback, privileged/ambiguous handling, unknown label, policy hash.

### F3 — Synchronized evidence workbench
- React Flow nodes and edges reflect selected case's recorded decisions and actual evaluated routes.
- Node/edge click opens contextual evidence; case selection updates graph, inspector and bottom dock.
- Improve graph fit after ELK layout and panel resize; preserve sensible zoom and selected case.
- Bottom dock: sortable/filterable paired case table, selected-case detail, regression filter and first-difference explanation.
- Distinguish pre-evaluation preview from post-evaluation evidence by both labels and interaction states.
- No fabricated token traces or provider timings.

### F4 — Matched evaluation and acceptance
- Same cohort, reference labels, evaluator and accounting boundary for baseline and candidate.
- Compute quality, escalation correctness, policy violations, failure rate, latency, execution costs and cost per verified successful outcome.
- Critical guardrails are mandatory; inconclusive evidence cannot authorize activation.
- Persist evaluation run, hashes, policy revision and per-case differences.
- Include a safe deterministic-replacement candidate for UO-AC-03, if absent; do not silently omit approved scope.

### F5 — Guarded local release, verification, restore
- Activate only exact frozen passing revision with explicit confirmation.
- Separate verification batch from pre-release acceptance cohort; do not reuse identical results as post-release proof.
- Inject controlled regression scenario; demonstrate restore to S0 and append-only session history.
- Explicitly local synthetic simulation; never suggest real deployment.

### F6 — Independent QA gate
- Successful clean dependency install and Next.js production build.
- Unit/integration tests for contracts, rules, evaluator, cost and release gating.
- Playwright browser journeys for Inspect→Design→Compare→Release, case selection, edge selection, changed outcome, editing invalidation, blocked candidate, eligible candidate, verification and restoration.
- Visual QA: desktop, narrow viewport, graph fit after resize, keyboard interactions and no console/runtime errors.
- Save reproducible commands, logs, screenshots and test evidence; no acceptance on screenshots alone.

## Acceptance checklist

- [ ] A selected case is traceable to observed classification, rule, route, attempt, cost and outcome.
- [ ] Graph, inspector and evidence table agree on case and policy revision.
- [ ] Preview counts derive from runtime-available fields and policy engine.
- [ ] Changed policy invalidates stale evaluation.
- [ ] Paired comparison identifies first recorded decision divergence.
- [ ] Aggregates reconcile to per-case/per-attempt records.
- [ ] Critical violations or insufficient evidence block activation.
- [ ] Deterministic alternative is demonstrated per UO-001.
- [ ] Exact evaluated revision is activated only in synthetic environment.
- [ ] Independent verification batch and restoration produce durable local history.
- [ ] Production build and browser tests pass; no runtime errors.
- [ ] No unsupported real-provider or real-savings claims.

## Risks and mitigations

- **Overengineering:** one synthetic workflow, minimal domain types, no backend.
- **Ground-truth leakage:** policy sees observed labels only; adversarial tests.
- **Fixture special-casing:** evaluate generic rules; prohibit candidate-ID gates.
- **Cost illusion:** derive costs from attempts and separately disclose modeled labor.
- **Visual truth gap:** distinguish projections from observed/replayed attempts.
- **Release confusion:** activation is simulated, local and revision-bound.
- **Unverified delivery:** fail release gate if npm build or browser test missing.
